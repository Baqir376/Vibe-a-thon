# Synapse CLI 0.1.9: issues found while building Synaptogenesis

Ready to file at https://github.com/2ndbrainlabs-ai/synapse-cli-ts/issues. Each one was reproduced on
Windows 11, Node 24, Python 3.12, `@2ndbrainlabs-ai/synapse-cli@0.1.9`, `@2ndbrainlabs-ai/synapse-mcp@0.0.4`.

---

## 1. Request-body fields silently dropped when typed `Literal[...]` or followed by a trailing comment

```python
from typing import Literal
from fastapi import FastAPI
from pydantic import BaseModel
app = FastAPI()
class Probe(BaseModel):
    plain: str
    commented: str  # trailing comment
    lit: Literal["a", "b"]
    after_lit: int = 0
@app.post("/probe")
def probe(body: Probe):
    """Probe."""
    return body
```
`synapse build --local --auto --all-endpoints --yes` generates
`def probe(plain: Any = None, after_lit: Any = None)`: `commented` and `lit` are missing from the tool and the
payload. Real impact: a required `reason: Literal[...]` on `POST /refunds` vanished, so every agent call returned 422.

## 2. Hosted Auto on Express: path params not templated, body fields not detected

For `app.get("/oncall/:region", ...)` and `app.post("/pages", (req, res) => { const { staff_id, message } = req.body ... })`,
the hosted tools have an empty input schema; the runner (0.0.4) only substitutes `{param}`, so it calls the literal
URL `/oncall/:region`, and POST bodies arrive empty (`Staff undefined not found`). `--smart-names` doesn't change it.
FastAPI projects work correctly in hosted mode.

## 3. Local Auto passthrough drops query parameters

`@app.get("/stock") def get_stock(warehouse_id: Optional[str] = None, sku: Optional[str] = None)` becomes
`def get_stock() -> dict` with no way to filter.

## 4. Passthrough tools hide API error bodies

Generated tools call `resp.raise_for_status()`, so the agent sees `422 Client Error: Unprocessable Entity for url`
instead of FastAPI's `{"detail": "...field required: reason"}` and cannot self-correct. Returning
`{"status_code", "body"}` on 4xx would let agents recover.

## 5. Custom mode composes on top of its own earlier outputs

After one `synapse build --custom` writes `process_refund_server.py` into the repo, the next Custom build scans it as
project source and generates `from process_refund_server import process_refund`. Deleting the old file breaks the new
tool. Suggest excluding `*_server.py` / files with the "Generated by Synapse" header from discovery.

## 6. `--local --auto` requires a model key even though plain Auto calls no model

`synapse build --local --auto --endpoints ...` exits with "Anthropic API key required" unless a provider key is set,
although the README states Auto without `--smart-names` calls no model. Workaround: `SYNAPSE_LLM_PROVIDER=ollama`.

## 7. Hosted MCP snippet prints `"SYNAPSE_API_KEY": "<your key>"`

Copying the printed snippet verbatim makes the runner fail with `Failed to fetch MCP config (401): Invalid or expired API key`.

## 8. `.synapse/surface_cache.json` stores endpoints under the key `"undefined"`

`"files": {"undefined": {}}` after a FastAPI scan, so the cached surface cannot be read back by tools.

## 9. Repeated local builds write numbered files instead of updating

`synapse_auto_server.py`, then `synapse_auto_server_2.py`, `_3.py`, … so the printed client config path changes
on every rebuild (README says rebuilds update the same server).

## 10. Generated servers need `mcp>=1.30,<2`

Servers import `mcp.server.fastmcp` (removed in `mcp` 2.x) and combine `from __future__ import annotations` with
`Any` hints, which crashes `mcp` 1.12 (`issubclass() arg 1 must be a class`). Pinning in the printed instructions
(`pip install "mcp>=1.30,<2"`) would help.

## 11. Hosted Auto marks optional body fields as required

`order_id: Optional[str] = None` on `POST /tickets` is required in the hosted tool's schema.

## 12. Custom-mode output quality depends heavily on documented return shapes

With `def check_refund_policy(...) -> dict` and no description of the returned keys, the composed tool read
`policy.get("refund_amount")` and `result.get("success")`, keys that never exist; it issued the refund and then
reported failure. Documenting the dict in the docstring fixed it. Worth a line in the docs, or a static check that
generated code only reads keys the callee returns.
