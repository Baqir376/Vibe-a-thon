# MCP setup

Synaptogenesis does not ship hand-written MCP servers. **Every MCP server is generated by Synapse CLI 0.1.9**, mostly at
runtime by the agent itself. This page shows exactly what gets generated and how to reproduce it by hand.

## The four systems

| System | Code | Synapse mode | Generated server |
|---|---|---|---|
| orders | `services/orders/main.py` (FastAPI, 12 endpoints) | hosted Auto | Synapse cloud config, served by `@2ndbrainlabs-ai/synapse-mcp` · server id `237bd6b1-daa2-40e6-9c5b-6411e49a68d0` |
| roster | `services/roster/main.py` (FastAPI, 6 endpoints) | hosted Auto | server id `28727e87-0bdd-49b1-92dc-442c6c36a793` |
| inventory | `services/inventory/main.py` (FastAPI, 12 endpoints) | local Auto | `synapse_auto_server.py` (passthrough), moved to `.synapto/grafts/` |
| tickets | `services/tickets/main.py` + `refunds.py` | local Auto + **Custom** | passthrough server + the fused `process_refund` tool in `.synapto/fused/` |

Account usage: 3 of 10 hosted MCP servers, 372 indexed lines (the third server is a hosted-mode probe of `tickets`).

## What the agent runs (you can run the same by hand)

```bash
# Auto, local: only the endpoints the question needs (this is a "graft")
cd services/inventory
SYNAPSE_LLM_PROVIDER=ollama synapse build --local --auto --endpoints "GET /stock/low,GET /products/{sku}/availability" --yes
#   → synapse_auto_server.py   (env: ENDPOINT_BASE_URL=http://127.0.0.1:8102)

# Auto, hosted: same idea, served by Synapse's runner
cd services/orders
synapse build --auto --endpoints "GET /shipments/delayed,GET /shipments/{shipment_id}/orders" --yes \
  --base-url http://127.0.0.1:8101 --server-name synapto-orders

# Drift Sentinel: rescan after a code change
synapse build --local --auto --all-endpoints --discover --yes

# Custom (fusion): compose internal functions into ONE tool
cd services/tickets
SYNAPSE_LLM_PROVIDER=groq synapse build --custom --local --yes \
  -q "Process a refund end to end: check the refund policy, refuse duplicates, issue the refund. One tool."
```

(`SYNAPSE_LLM_PROVIDER=ollama` only satisfies the CLI's key preflight; plain local Auto calls no model. See issue #6 in
`docs/synapse-issues.md`.)

## Attaching a grafted server to Claude Desktop or Cursor

The snippets Synapse prints work unchanged once the placeholders are filled in:

```json
{
  "mcpServers": {
    "synapto-orders": {
      "command": "npx",
      "args": ["-y", "@2ndbrainlabs-ai/synapse-mcp"],
      "env": {
        "SYNAPSE_SERVER_ID": "237bd6b1-daa2-40e6-9c5b-6411e49a68d0",
        "SYNAPSE_API_KEY": "<your Synapse key>",
        "ENDPOINT_BASE_URL": "http://127.0.0.1:8101"
      }
    },
    "inventory-graft": {
      "command": "python",
      "args": ["<path>/.synapto/grafts/inventory_<id>.py"],
      "env": { "ENDPOINT_BASE_URL": "http://127.0.0.1:8102" }
    }
  }
}
```

Synaptogenesis itself connects to these servers over stdio with the official `mcp` Python client
(`synaptogenesis/graft.py::_connect`), exposes only the requested tools to the model, and keeps pruned connections
dormant for instant reuse.

## Policy

`policy.yaml` decides what may ever be grafted (`deny`), which methods need a human (`require_approval_methods`) and the
maximum live tool count. Write endpoints are approved when grafted **and** on every call.
